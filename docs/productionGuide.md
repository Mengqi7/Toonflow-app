# Toonflow 短剧与漫剧完整操作指南

> 适用对象：第一次使用 Toonflow 的创作者、新入职制作人员，以及接管项目制作任务的 AI Agent。  
> 目标：从“只有一个创意、小说或剧本”，推进到可审阅的剧本、角色/场景/道具资产、分段提示词、图片与视频片段，并如实交付当前项目实际完成的成果。  
> 能力基线：`develop-new` 分支，2026-09-30。本文只描述当前项目已经具备的能力。

---

## 1. 先理解 Toonflow 的工作方式

Toonflow 不是传统剪辑软件，也不是点一次按钮就自动生成整部短剧的软件。它是一套“项目工作区 + 创作画布 + AI Agent + 生成节点”的制作环境。

一部作品通常沿以下主线完成：

```text
创意 / 小说 / 剧本
        ↓
确定本次制作范围和规格
        ↓
完成并确认可制作剧本
        ↓
提取角色、场景、道具和声音需求
        ↓
设计并生成可复用资产
        ↓
把剧情拆成可生成的视频片段
        ↓
为每个片段编写正式视频提示词
        ↓
连接真实参考图，设置模型与规格
        ↓
逐段生成、预览、修订和采用
        ↓
整理已采用片段及顺序
        ↓
进入外部后期，或在确有工具时完成合成
```

### 1.1 三个最重要的概念

#### 工作区

一个本地文件夹就是一个 Toonflow 项目。画布、文档、图片、视频、音频和 Agent 会话都会保存在这个文件夹里。

#### 画布

画布用节点组织制作资料。文本节点承载剧本和提示词，图片/视频/音频节点固定素材，生成节点负责调用模型，连线负责把真实素材传给生成节点。

#### Agent

Agent 可以帮用户读剧本、规划资产、搭建节点、填写提示词、连接参考和检查进度。Agent 不能绕过模型配置、用户授权或真实结果；它也不能把“已开始生成”说成“已经完成”。

### 1.2 当前边界

Toonflow 当前可以完成：

- 剧本创作和小说改编；
- 角色、场景、道具设计；
- 图片资产生成；
- 视频片段生成；
- 音频生成或导入；
- 3D 场景和镜头预演；
- 素材、画布、文档和制作状态管理；
- 由 Agent 或 MCP 操作项目。

Toonflow 当前**没有完整的多轨时间线剪辑器**。如果作品需要精确裁切、字幕排版、转场、配乐、混音和最终封装，通常需要把已采用片段交给剪映、Premiere、DaVinci Resolve 等后期软件。只有实际安装并启用了相应合成工具时，才能在 Toonflow 内执行对应合成；不能把若干视频节点直接称为“完整成片”。

## 2. 短剧和漫剧如何选择制作路线

### 2.1 短剧路线

适合真人感、电影感、连续动作较多、镜头运动明显的内容。

重点是：

- 人物身份、服装和脸部稳定；
- 场景空间、站位和轴线连续；
- 对白、动作和反应在时长内可完成；
- 相邻视频片段能接戏；
- 视频模型的运动、声音和参考能力匹配剧情。

推荐结构：

```text
定稿剧本
  → 角色三视图/特写参考板
  → 场景主视图和关键道具
  → 分段视频提示词
  → 每段一个视频生成节点
  → 逐段验收和记录实际结束状态
```

### 2.2 漫剧路线

适合漫画、插画、二维动画、动态漫画、旁白驱动或镜头运动较轻的内容。

重点是：

- 画风、角色外观和配色统一；
- 每个画面表达清晰，构图为字幕留出空间；
- 把复杂动作拆成更稳定的姿态或短动作；
- 明确哪些文字应后期叠加，避免模型直接生成大量字幕；
- 可以先形成关键画面，再制作轻运动视频。

推荐结构：

```text
定稿剧本/旁白稿
  → 角色与场景风格资产
  → 按叙事节拍规划关键画面
  → 图片生成节点产出画面
  → 必要画面进入视频生成节点做轻运动
  → 音频/旁白与片段索引
```

### 2.3 混合路线

可以用 3D 导演台预演空间和运镜，再生成风格化图片或视频；也可以用插画资产约束电影感视频。混合路线仍然遵循同一原则：先定稿内容，再做资产，最后生成片段。

## 3. 开始前的准备

### 3.1 普通用户启动

使用已安装的桌面版时，直接打开 Toonflow。Windows 需要可用的 Microsoft Edge WebView2 Runtime。

使用浏览器版或源码部署时，管理员需先启动 Web 和 Server。普通制作人员只需访问管理员提供的 Toonflow 地址。

### 3.2 源码环境启动（开发者）

首次运行：

```sh
bun install
bun run dev:plugins
bun run dev
```

浏览器访问 `http://localhost:5173`。`dev:plugins` 用于构建内置节点和工具，首次启动或这些插件发生变化时必须执行。

桌面开发使用：

```sh
bun run dev:desktop
```

桌面开发加载构建后的 Web，不是 Vite 热更新页面。

### 3.3 准备一个工作目录

每个项目使用一个独立文件夹，例如：

```text
D:\ToonflowProjects\雨夜来客01
```

建议：

- 新项目选择空文件夹；
- 路径不要含系统保留字符；
- 不要把两个项目放进同一个工作区根目录；
- 不要让多个 Toonflow 实例同时编辑同一个项目；
- 制作中不要在资源管理器里随意移动正在使用的文件；
- 重要项目定期备份整个工作区。

### 3.4 准备输入资料

至少准备下面一项：

- 一句话创意；
- 故事梗概；
- 小说章节；
- 已定稿剧本；
- 已有角色图、场景图、视频或音频；
- 上一集已采用片段和连续性说明。

资料越明确，返工越少。推荐同时提供：

| 项目 | 示例 |
| --- | --- |
| 本次范围 | 第 1 集，60 秒 |
| 作品类型 | 竖屏古风漫剧 |
| 画幅 | 9:16 |
| 语言 | 中文普通话 |
| 画风 | 国风厚涂、低饱和、雨夜冷色 |
| 目标平台 | 抖音/视频号/B 站 |
| 声音 | 角色原声对白，或旁白驱动 |
| 禁止项 | 不改结局、不增加人物、不出现水印 |
| 已有素材 | 女主参考图、客栈场景图、上一段视频 |

## 4. 首次配置模型

### 4.1 快速配置

首次打开时进入“快速开始”：

1. 选择“登录 TF-Router 自动配置”；
2. 在内嵌页面登录或注册；
3. 等待 Toonflow 自动读取并保存文本模型和媒体模型；
4. 配置完成后进入首页。

也可以选择“添加私有提供商”，手工填写 API 地址、协议、API Key 和模型。

### 4.2 检查文本模型

打开“设置 → 文本模型”，确认至少有一个模型。文本模型用于：

- Agent 对话；
- 剧本创作和改编；
- 分析资产与镜头；
- 3D 导演方案等 AI 能力。

如果模型列表为空，Agent 不能正常工作。

### 4.3 检查媒体模型

打开“设置 → 媒体模型”，确认实际任务需要的类型：

- 图片模型：角色、场景、道具、关键画面；
- 视频模型：剧情视频片段；
- 音频模型：配音、旁白、音效或音乐，取决于供应商能力。

模型能力不是统一的。不同模型可能支持不同的：

- 画幅；
- 分辨率；
- 视频时长；
- 文生图、图生图、文生视频、首尾帧、多参考；
- 原生音频；
- 音频输入。

必须以生成节点实时显示的选项为准，不能照搬其他模型的参数。

### 4.4 检查节点和工具

进入“设置 → 插件市场”，确认至少启用：

- 文本、图片、视频、音频节点；
- 图片生成、视频生成节点；
- 需要时启用 3D 导演台；
- 画布操作、工作区文件、提问器等 Agent 工具。

需要媒体处理时，检查 FFmpeg 状态。若应用提示缺少 FFmpeg，在插件市场中下载或配置可用版本。

## 5. 创建项目

### 5.1 灵感模式创建

适合只有创意或梗概的用户：

1. 在首页“创作描述”中输入需求；
2. 点击“选择工作目录”；
3. 选择一个空文件夹；
4. 选择文本模型和推理等级；
5. 点击发送按钮；
6. Toonflow 创建 `画布1.json` 并进入工作区；
7. 首条描述自动发送给 Agent。

推荐首条描述：

```text
我要制作一部 60 秒、9:16 的古风悬疑漫剧。主角是一名年轻女捕快，雨夜在客栈发现一封只写着自己名字的血书。先不要生成图片或视频。请使用 workflow 技能，先和我确认本次范围，再给出完整可审阅剧本和资产清单。
```

### 5.2 添加空项目

适合准备手工搭建画布的用户：

1. 首页点击“添加项目”；
2. 选择空目录；
3. 进入工作区；
4. 在画布空白处双击或右键；
5. 选择“添加节点”。

### 5.3 导入已有项目

1. 首页点击“导入项目”；
2. 选择包含 Toonflow 画布 JSON 的目录；
3. 打开项目；
4. 先检查画布、素材路径和 Agent 历史；
5. 不要立即重生成，先确认当前采用版本和缺项。

项目列表中的“重命名”只改显示名，“移除”只从列表移除，都不会修改或删除磁盘目录。

## 6. 熟悉工作区界面

### 6.1 画布和文档

顶部中间可以切换：

- **画布**：节点、素材、生成和流程组织；
- **文档**：编辑 Markdown 和画布中的文本输出。

切换面板时文档会自动保存。退出项目时应用会尝试保存画布和文档；若出现保存失败，不要直接强制退出，先重试并检查目录权限。

### 6.2 Agent 面板

Agent 默认显示在工作区一侧，可以拖动、调整大小或收起。Agent 面板用于：

- 输入创作要求；
- 粘贴图片或视频；
- 用 `@` 提及画布、节点输出、素材和文件；
- 审阅 Agent 的工具调用和提问；
- 停止生成；
- 切换模型和推理等级；
- 新建或打开历史对话。

### 6.3 手工添加节点

在画布空白处双击或右键：

```text
操作菜单 → 添加节点 → 选择节点类型
```

常用节点：

- 文本；
- 图片；
- 图片生成；
- 视频；
- 视频生成；
- 音频；
- 3D 导演台。

也可以把本地图片、视频、音频或文本直接拖入画布，或选择“上传”。

### 6.4 连接节点

从来源节点的输出端口拖到目标节点的输入端口。只允许兼容类型连接。

正确用途：

- 图片节点 → 图片生成节点：作为图片参考；
- 图片节点 → 视频生成节点：作为角色、场景、首帧或多参考；
- 视频/音频节点 → 支持相应输入的视频生成节点；
- 文本节点 → 支持 STRING 输入的节点。

注意：生成节点已经有自己的提示词输入框。若把完整剧本文本节点也连接进去，当前实现可能把全文追加到提示词，造成重复或超长。正式生成前必须检查实际输入和提示词。

### 6.5 多画布建议

点击左上画布名称打开列表，可新增、切换、重命名或删除画布。

推荐按规模选择：

- 小项目：全部放在一张画布；
- 中型项目：`01剧本与资产`、`02视频片段`；
- 多集项目：每集一张画布，公共资产另设一张画布。

不要为了形式创建大量空画布。切换画布不会自动中止所有后台节点任务，但关闭项目或页面可能中止请求。

## 7. 总制作流程

完整制作分为七个阶段。每个阶段都有明确成果和确认点。

| 阶段 | 主要成果 | 是否消耗媒体算力 |
| --- | --- | --- |
| 1. 范围与输入 | 本次范围、规格、资料覆盖情况 | 否 |
| 2. 可制作剧本 | 定稿剧本和必要制作简报 | 否 |
| 3. 资产规划 | 角色、场景、道具、声音清单 | 否 |
| 4. 资产制作 | 已采用的真实图片/音频资产 | 是 |
| 5. 视频规划 | 分段、时长、正式提示词和参考绑定 | 否 |
| 6. 片段生成 | 真实视频结果及采用决定 | 是 |
| 7. 交付 | 已采用素材索引、顺序、缺项和后期说明 | 视情况 |

三个确认不能混为一谈：

1. **内容确认**：剧本、设计或提示词可以继续使用；
2. **生成授权**：同意按明确方案消耗算力；
3. **结果采用**：看过实际结果并决定作为正式素材。

“继续”“看起来可以”或确认剧本，不自动等于同意生成媒体。

## 8. 阶段一：锁定本次范围

### 8.1 必须确定的事项

- 本次制作哪一集、哪一场或哪一段；
- 输入是创意、小说还是定稿剧本；
- 目标总时长；
- 横屏、竖屏或方形画幅；
- 短剧、漫剧或混合路线；
- 语言、对白、旁白和字幕策略；
- 视觉风格；
- 已有素材和必须沿用的版本；
- 是否允许改剧情、删台词或增加人物；
- 本轮做到剧本、资产、提示词、片段还是交付。

### 8.2 新人填写模板

```text
项目名称：
本次制作范围：
输入资料：创意 / 小说 / 剧本 / 续作
目标类型：短剧 / 漫剧 / 混合
目标时长：
画幅：
语言与声音：
视觉风格：
必须保留：
禁止修改：
已有素材：
本轮期望交付：
```

### 8.3 AI 执行规则

AI 应先读取当前消息、指定文件和真实画布，只询问会改变作品且无法推断的关键信息。不要让用户重复已经提供的内容，也不要先生成媒体。

AI 推荐开场提示：

```text
请先使用 workflow 技能。读取我指定的内容后，只完成“范围确认和制作简报”。区分已知事实、创作提案和未知项；不要创建媒体生成任务，也不要消耗算力。
```

### 8.4 阶段完成标准

- 能用一句话说清本次交付；
- 输入覆盖范围明确；
- 硬性规格明确；
- 已知、未知和待提案项分开；
- 没有把尚未确认的创意当成事实。

## 9. 阶段二：完成可制作剧本

### 9.1 从创意开始

围绕以下问题发展故事：

- 谁想要什么；
- 遇到什么阻碍；
- 做了什么选择；
- 付出什么代价；
- 最后发生什么改变。

不要急着写镜头参数。先让剧情通过人物行动和因果成立。

推荐剧本格式：

```text
本次范围与目标：
视觉、语言和声音要求：
总时长估算及硬约束：

场01｜客栈大堂｜雨夜｜女捕快、掌柜
女捕快推门进入，雨水顺斗笠边缘滴落。掌柜停止擦杯，目光落向柜台下方。
掌柜：客官，打烊了。
女捕快没有回答，将沾泥的令牌压在桌面。
音效：门外雷声；室内木梁轻响。
本场结束状态：掌柜认出令牌，右手仍藏在柜台下。
```

### 9.2 从小说改编

1. 确认本次改编的章节或片段；
2. 完整读取约定范围；
3. 记录事件顺序、人物关系、重要对白、时间地点、道具变化和悬念；
4. 将心理活动转为可见行动、对白、旁白或画内信息；
5. 把新增、删并、改视角等内容标为“改编提案”；
6. 未经授权，不改变原著关键事实、结局或人物关系。

长篇小说不要只凭摘要声称已经读完。应记录已读范围和下次读取起点。

### 9.3 从定稿剧本开始

- 保存并固定用户指定的版本；
- 保留场号、事件、对白、OS/VO 和制作要求；
- 不重新从零写故事；
- 只提取后续制作需要的角色、场景、道具、声音和规格；
- 若时长与完整对白明显冲突，提出延长、拆段或获得删改授权，不擅自删词。

### 9.4 漫剧剧本的额外要求

- 标明旁白、对白、字幕和画内文字；
- 每个叙事节拍应能落到一个清晰画面或短动作；
- 长对白预留足够口播和字幕阅读时间；
- 避免在单个画面塞入过多人物、动作和文字；
- 明确哪些字幕后期添加，不要求生成模型把长段文字画进图里。

### 9.5 保存剧本

推荐两种方式：

#### 画布文本节点

1. 添加“文本”节点；
2. 命名为“第01集定稿剧本”；
3. 粘贴或让 Agent 写入完整剧本；
4. 切到“文档”面板继续编辑；
5. 等待“已保存”。

#### Markdown 文件

1. 切换到“文档”；
2. 点击文件树顶部“新建 Markdown 文件”；
3. 命名为 `episode01Script.md`；
4. 编辑并等待自动保存。

### 9.6 固定确认版本

在提交用户确认前，应保存一个独立历史快照，例如：

```text
history/episode01ScriptV1.md
```

用户确认绑定的是该具体版本。等待确认期间若正文被修改，旧确认不能自动覆盖新内容。

### 9.7 阶段完成标准

- 场次、人物、空间、动作、对白和声音完整；
- 剧情重要信息在画面或声音中可表达；
- 估算时长合理；
- 用户确认具体版本；
- 未授权改编项仍标明待确认。

## 10. 阶段三：提取资产清单

### 10.1 只做真正需要的资产

资产用于稳定身份、空间和物件，不用于替代剧本。

应该建立独立资产的对象：

- 会反复出现或需要跨段保持一致的角色；
- 承载剧情行动的主要场景；
- 会被拿取、交接、破坏或特写的关键道具；
- 持续换装、伤势、变身或天气状态。

通常不必单独做资产：

- 只在对白中提到、从未出镜的人；
- 纯声音角色；
- 普通背景装饰；
- 瞬时表情；
- 一次性的局部动作。

### 10.2 资产清单模板

| 标识与名称 | 类型/状态 | 使用范围 | 固定锚点 | 已有真实素材 | 本次处理 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| C01 女捕快·基础态 | 角色 | 场01–06 | 年龄、脸型、发式、黑红捕快服、腰牌 | `assets/hero.png` | 复用或补参考板 | 待验收 |
| S01 雨夜客栈 | 场景 | 场01–03 | 门、柜台、楼梯相对位置 | 缺失 | 生成主视图 | 待生成 |
| P01 血书 | 道具 | 场02–05 | 折痕、纸张、血字位置 | 缺失 | 生成参考板 | 待生成 |

### 10.3 角色资产标准

新角色默认制作一张横向参考板：

1. 头部特写；
2. 正面完整全身；
3. 右侧 90° 完整全身；
4. 背面完整全身。

要求：

- 四个视角是同一角色、同一状态；
- 发型、脸部、体型、服装、配色和携带物一致；
- 全身不裁头、不截脚；
- 中性表情和自然静态姿势；
- 简洁背景；
- 不混入剧情动作和其他人物；
- 不生成无关标注、水印和说明文字。

### 10.4 场景资产标准

一张主视图至少交代：

- 前景入口；
- 中景主要活动区；
- 后景边界；
- 门、窗、楼梯、道路等通道；
- 稳定地标；
- 人物行动所需空间；
- 时段、天气、材质和光照。

独立场景图不要夹带人物、人影或剧情动作。

### 10.5 道具资产标准

关键道具可使用 2×2 参考板：

- 正面；
- 右侧 90°；
- 背面；
- 局部细节。

四格必须是同一个物件，结构、材质、尺寸关系和状态一致。不要带人物、手臂或无关文字。

### 10.6 声音清单

为每个需要稳定声音的角色记录：

- 音区；
- 音色；
- 语速；
- 口音；
- 表达习惯；
- 画内对白、OS、VO 或旁白身份。

有对白不等于必须先上传音色样本。若视频模型支持原生声音，可用文字声线；只有真实模型支持且确有素材时才连接音频参考。

### 10.7 阶段完成标准

- 清单覆盖本次完整剧本，而不只覆盖第一个片段；
- 同一身份别名已合并；
- 角色、场景、道具状态变化有适用范围；
- 已有素材、缺失素材和设计提案分开；
- 用户确认关键设计方向。

不论由人还是 AI 操作，生成前都应明确：

- 生成对象和数量；
- 使用的 provider 和模型；
- 比例与分辨率；
- 完整提示词；
- 真实参考图和用途；
- 执行次数；
- 算力消耗，无法查询时写“未知”。

用户同意这一具体方案后再生成。更换模型、改变提示词、增加数量或额外重试，需要确认原授权是否覆盖。

### 11.5 生成中的状态

生成按钮变为停止状态或节点显示 loading，只表示任务正在进行。不要关闭项目或切走整个页面。生成完成后，节点会显示真实输出；如果只有“generating”回执，Agent 不能宣称完成。

### 11.6 资产验收

检查图片：

- 身份是否正确；
- 人物数量是否正确；
- 脸、发型、服装和配色是否一致；
- 手脚和身体是否完整；
- 多视图是否是同一对象；
- 场景空间关系是否清楚；
- 道具结构和状态是否一致；
- 是否出现水印、乱码或多余文字；
- 文件是否能正常打开。

结果可分为：

- 已采用；
- 候选，需比较；
- 需局部修改；
- 作废。

### 11.7 固定已采用资产

已采用图片不要只留在生成节点：

1. 使用节点菜单“保存到素材库”，或下载/记录真实文件；
2. 添加独立“图片”节点；
3. 将已采用文件挂载到图片节点；
4. 命名为“C01 女捕快 基础态 已采用”；
5. 后续视频只连接已采用资产，而不是未确认的生成候选。

修订时新增候选节点，不要覆盖仍被下游使用的已采用结果。

## 12. 阶段五：视频分段与提示词

### 12.1 先理解“片段”和“镜头”

- **镜头**：一个连续摄影表达，可有景别、角度和运镜；
- **生成片段**：一次视频模型调用的完整内容，可以包含一个或多个镜头；
- 默认一个剧情片段对应一份正式提示词和一个视频生成节点；
- 不需要为每个镜头都单独生成一张关键帧。

### 12.2 分段原则

按完整动作、对白、反应和模型时长切分，而不是为了凑固定秒数。

每段必须满足：

- 对白能按自然语速说完；
- 关键动作有开始、过程和结果；
- 必要反应和停顿有时间；
- 不超过实时模型支持的单次时长；
- 切点不破坏重要因果；
- 相邻连续段有明确接戏状态。

### 12.3 Seedance 特别规则

当前内置 `workflow` 对“已有可执行定稿剧本/时间轴，并开始制作、生成或修订视频”的任务采用 Seedance 导演流程。

- 这是自动路由：只要已有可执行剧本/时间轴且任务是制作、继续、生成或修订视频，即使用户没有说“Seedance”，也进入此流程；
- 用户已经指定 Seedance 2.0 或 2.5：直接按对应规范规划；
- 用户未指定：AI 必须先只问一次“Seedance 2.0 还是 2.5？”；
- 必须先按内置 `workflow` 的 PART A 完成全片规划和正式提示词，再读取画布配置并执行；不能先读节点默认配置来替代导演规划；
- 进入该阶段后，提示词只按 PART A A0–A12 生成，不混用旧分镜模板、通用方法或子 Agent 另写的另一套规则；
- 2.0 单段硬上限为 15 秒，每批最多交付 6 段；
- 2.5 单段硬上限为 30 秒，每批最多交付 3 段；
- 批次只控制一次交付容量，不改变全局段号、剧情顺序或连续性；
- 理论最少段数只是下限，实际还要看对白和动作密度；
- 剧情顺序、关键对白、人物关系和结局不能为了分段而改变；
- 画幅、分辨率和音频是执行参数，不能替代目标模型选择；
- 若实时节点不支持已选模型，必须报告能力冲突，不能静默换成默认模型。

若任务尚未进入视频制作阶段，例如仍在创意、剧本、资产设计或单纯咨询阶段，则不触发该视频提示词路由；但所有媒体操作仍须遵守模型实时能力、真实参考、算力授权和结果验收原则。

### 12.4 分段规划表

| 片段 | 剧情范围 | 预计时长 | 人物/状态 | 场景/状态 | 道具 | 声音 | 与前后段关系 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| V01 | 女捕快进门并出示令牌 | 10s | C01 基础态，斗笠带雨 | S01 雨夜客栈 | 腰牌 | 掌柜一句对白、雷声 | 独立开场，结束时掌柜手藏柜台下 |
| V02 | 掌柜抽刀，女捕快侧身躲开 | 8s | 同上 | 同上，桌上杯子被碰倒 | 短刀、杯子 | 木桌碰撞 | 连续接 V01 末态 |

### 12.5 正式提示词应包含什么

每段提示词至少包含：

- 目标和剧情边界；
- 人物身份、当前外观和出镜状态；
- 场景与时段；
- 世界空间关系和画面位置；
- 按时间轴排列的动作、对白和反应；
- 镜头、景别、角度、必要运镜；
- 光线和色彩；
- 声音方向；
- 真实参考绑定；
- 必须保持的内容；
- 需要避免的常见崩坏和无关文字。

### 12.6 普通视频提示词模板

```text

人物与状态：
- C01 女捕快：黑发高束、右眉尾浅疤、黑红捕快服、腰间铜令牌，斗笠和肩部带雨水。
- C02 掌柜：五十岁、灰布长衫，站在柜台内，右手起初在台面上。

场景与空间：
雨夜客栈大堂。木门位于画面左后方，柜台位于右侧，女捕快从木门进入并停在柜台外，掌柜始终位于柜台内。

时间轴：
00:00–00:03，中远景，木门被风推开，女捕快逆着门外冷蓝雨光进入，门内暖黄灯光照亮她半侧脸；镜头缓慢向后稳定移动。
00:03–00:06，中景，女捕快走到柜台前停下，取下腰间铜令牌，手部动作完整可见。
00:06–00:09，近景，她把令牌压在木柜台上；掌柜停止擦杯，视线先落到令牌，再抬向她。
00:09–00:10，掌柜保持克制，右手缓慢移向柜台下方，动作尚未完成，为下一段保留。

对白与声音：
00:04–00:06，掌柜低声说：“客官，打烊了。”
门外持续雨声，00:09 远处雷声；无背景旁白。

保持：人物外观、服装、令牌结构、柜台和楼梯位置稳定；动作顺序不可改变。
避免：新增人物、重复肢体、令牌消失或换手、面部漂移、自动生成字幕、水印和乱码。
```

### 12.7 漫剧提示词调整

漫剧可弱化复杂运镜，强调构图和轻动作：

- 保持线稿、上色方式和人物比例；
- 限制每段动作数量；
- 使用轻微推拉、景深层移动、衣摆/雨水/灯火等局部动态；
- 不要求模型生成长字幕；
- 对旁白驱动内容，画面只表达对应信息，不必强行口型同步；
- 给后期字幕保留干净区域。

示例：

```text
二维国风漫剧，保持角色参考的线稿粗细、面部比例和低饱和配色。竖屏构图，人物位于画面下部与右侧，左上保留干净的字幕安全区。女捕快推门进入后只做抬头、摘斗笠、放下令牌三个清晰动作；背景以雨幕、灯笼轻晃和前后景微视差产生运动，不增加复杂打斗。禁止模型内生成字幕、气泡、乱码和水印。
```

### 12.8 提示词审查

生成前逐段检查：

- 是否覆盖原剧本全部事件；
- 是否改动了剧情顺序或对白；
- 是否塞入过多动作；
- 对白是否能在时长内说完；
- 人物站位、朝向和移动是否合理；
- 道具持有人和状态是否连续；
- 场景门、窗、楼梯等位置是否前后一致；
- 参考绑定是否真实存在；
- 是否要求模型生成无必要文字；
- 是否有相互冲突的镜头指令；
- 是否对高风险动作做了简化。

## 13. 阶段六：搭建视频生成节点

### 13.1 手工搭建

每个片段建立一个视频生成节点：

1. 添加“视频生成”节点；
2. 命名为 `V01 进店亮令牌 候选1`；
3. 选择真实可用的视频模型；
4. 选择时长、分辨率、比例、模式和是否生成音频；
5. 写入 V01 完整提示词；
6. 把本段需要的已采用图片/视频/音频节点连接到输入；
7. 检查节点顶部或底部显示的参考顺序；
8. 首尾帧模式下特别确认第一张、第二张图片的语义；
9. 不连接本段不需要的资产；
10. 生成前再次核对配置和用户授权。

### 13.2 引用顺序

当提示词使用 `{{ref 1}}` 等编号时，编号必须与视频生成节点的真实参考顺序一致。

不要用资产清单顺序猜编号。每次更改连线或拖动参考顺序后，都要重新检查：

- 来源节点；
- 来源端口；
- 目标输入；
- 当前排序；
- 图片、视频、音频类型；
- 是否有尚未生成完成的空引用。

空引用不能被悄悄跳过，否则后面的编号会错位。

### 13.3 首尾帧模式

某些模型支持：

- 首帧；
- 尾帧；
- 首尾帧；
- 首帧可选等模式。

必须根据节点实时提示理解顺序。当前界面可能提示“仅一张图片时作为尾帧；两张图片按顺序作为首帧、尾帧”。不要假设所有供应商一致。

### 13.4 AI 操作画布的正确方式

AI 不应直接修改画布 JSON。应按以下顺序：

1. 查询当前画布和可用节点类型；
2. 查找已有剧本、资产和生成节点；
3. 读取目标节点必要字段；
4. 添加节点并使用返回的真实 ID；
5. 查询节点注册的函数 schema；
6. 调用 `node:setPrompt`、`node:setConfig` 等真实函数；
7. 读取端口和已有连线；
8. 连接真实素材；
9. 回读并核对；
10. 保存后再报告。

推荐给 AI 的指令：

```text
请使用 workflow 和 canvas。只处理 V01：先读取当前画布中的定稿剧本、已采用资产和真实节点能力，搭建一个视频生成候选节点并填写已经确认的提示词，连接实际需要的参考素材。不要启动生成。完成后列出节点 ID、模型候选、真实参考顺序和仍需我确认的参数。
```

### 13.5 生成前最后确认卡

```text
生成对象：V01 进店亮令牌
数量：1 个视频候选
模型：<providerId>/<modelId>
规格：10 秒，1080p，9:16，原生音频开启/关闭
模式：文生视频 / 多参考 / 首尾帧
完整提示词：<全文>
参考：
1. C01 女捕快基础态 → 身份与服装
2. S01 雨夜客栈 → 空间和材质
执行次数：1
算力消耗：<可靠报价或“未知”>
```

用户明确同意后才能点击生成。

## 14. 阶段七：生成、验收和采用视频

### 14.1 启动生成

点击视频生成节点的发送按钮。生成期间：

- 不关闭项目；
- 不更换工作区；
- 不改该节点的提示词、模型或引用；
- 需要时可点击停止；
- 独立且不依赖本段结果的其他节点可以继续准备。

### 14.2 失败时不要盲目重试

先确认：

- 请求是否实际失败；
- 是否已经产生了新输出；
- 模型是否返回内容安全或参数错误；
- 参考文件是否存在；
- 模式与参考数量是否匹配；
- 页面是否被关闭或切换；
- 原授权是否包含重试次数。

不明确时先检查节点输出。盲目重试可能重复消耗算力。

### 14.3 视频验收清单

#### 剧情

- 事件是否完整；
- 动作顺序是否正确；
- 对白是否缺失、错人或被改写；
- OS、VO 和画内对白是否正确；
- 有没有新增人物或事件。

#### 人物

- 脸、发型、服装、体型是否稳定；
- 人数是否正确；
- 手指、四肢、脸部是否变形或融合；
- 人物是否穿模、闪现或复制。

#### 道具

- 是否突然消失、复制、变形或换手；
- 尺寸和结构是否稳定；
- 拿取、交接、放置的过程是否完整。

#### 场景

- 门、窗、楼梯和家具位置是否稳定；
- 镜面、玻璃、影子是否错误复制人物；
- 光线、天气和时间状态是否一致；
- 人物是否在空间中不合理跳位。

#### 声音

- 说话人是否正确；
- 台词是否完整；
- 语速和音色是否可用；
- 环境音是否抢对白；
- 是否出现不需要的音乐或旁白。

#### 技术规格

- 文件能否播放；
- 比例、分辨率和时长是否符合要求；
- 是否有黑帧、花屏、卡顿和音画不同步。

### 14.4 AI 无法完整审片时

文件存在或出现缩略图，不代表 AI 看过完整视频、听过全部声音。若当前工具没有视频理解能力，AI 应请用户预览并反馈：

```text
请确认：
1. 是否采用该片段；
2. 明显问题及发生时间；
3. 片段结束时人物位置、朝向、姿势和持物；
4. 下一段是否需要紧接当前结束状态。
```

状态中应写“用户预览采用”，并注明 Agent 未核验项。

### 14.5 连续片段的接戏

只有相邻段在时间和空间上连续时，才强制接戏。记录前段真实结束状态：

- 人物世界位置；
- 画面位置和朝向；
- 姿势和动作进度；
- 道具所在手和状态；
- 场景变化；
- 持续声音；
- 已发生事件。

这些内容成为下一段的初始事实。不要用计划中的结尾替代真实生成结果，也不要把穿帮升级成新剧情。

### 14.6 修订策略

按问题根因修改：

| 问题 | 优先处理 |
| --- | --- |
| 人脸或服装漂移 | 检查角色参考、身份锚点和出镜人数 |
| 手部/物件穿帮 | 简化同时动作，写清接触顺序和持有人 |
| 道具消失或复制 | 每个时间段写明道具位置与状态 |
| 空间跳变 | 补世界坐标、出入口和人物相对位置 |
| 动作太快 | 减少动作或延长片段，不堆更多形容词 |
| 对白说不完 | 延长、拆段，或在获得改稿授权后压缩 |
| 镜头混乱 | 删除冲突运镜，保留一个主镜头意图 |
| 漫剧画风漂移 | 强化参考风格锚点，减少复杂运动和光照变化 |
| 多余字幕/乱码 | 明确禁止模型文字，改由后期添加 |

修改后创建新候选，保留旧视频和旧提示词，不覆盖已采用版本。

### 14.7 采用结果

用户确认采用后：

1. 记录实际文件路径；
2. 记录生成节点和尝试版本；
3. 记录实际模型、参数、提示词和参考；
4. 记录用户采用依据；
5. 用独立视频节点固定已采用文件；
6. 后续只让真正依赖该片段的内容引用它。

## 15. 音频、旁白和字幕

### 15.1 音频路线

根据模型和作品选择：

- 视频模型原生生成对白和环境音；
- 由 Agent 的媒体生成工具调用已配置的音频模型，单独生成角色语音或旁白；
- 导入真人录音；
- 后期软件中统一配音和混音。

当前画布只有用于上传、替换和播放已有文件的“音频”节点，没有独立的“音频生成”节点。需要单独生成音频时，应让 Agent 调用已启用的媒体生成工具；工具不可用时在外部制作后导入。生成或导入后，用“音频”节点固定真实文件。若视频模型确实支持音频参考，再连接到对应视频生成节点。

### 15.2 旁白型漫剧

推荐先锁定：

- 旁白完整文本；
- 自然语速和停顿；
- 每段旁白对应画面；
- 哪些对白需要口型，哪些只作画外声音；
- 每张画面停留时间。

不要让单个短片段承载超出自然语速的旁白。

### 15.3 字幕策略

对话字幕、章节标题和说明文字通常在后期添加。生成提示词中应写：

```text
画面中不生成字幕、对白文字、气泡、Logo、水印或无关字符；为后期字幕保留安全区域。
```

剧情中真实存在的招牌、信件、屏幕文字属于实体资产文字，要明确内容、位置和是否必须可读；它们与后期字幕不同。

## 16. 3D 导演台的使用

3D 导演台适合：

- 复杂空间关系；
- 多人物站位；
- 需要提前设计运镜；
- 打斗、追逐或长镜头预演；
- 为图片/视频提供构图参考。

基本流程：

1. 添加“3D 导演台”；
2. 连接相关文本、图片或视频参考；
3. 描述场景、人物动作和镜头要求；
4. 生成导演方案；
5. 选择方案并预览动画；
6. 进入取景，用鼠标调整方向，WASD 移动，空格上升，Shift 下降，滚轮调焦；
7. 添加并排序关键帧；
8. 设置画幅、网格、天空和光照；
9. 导出关键帧为图片节点，或导出预演为视频节点。

3D 预演不是最终生成视频。它主要用于验证空间、站位、构图和运镜，并为后续媒体生成提供参考。

## 17. 制作状态和版本管理

### 17.1 为什么必须记录状态

多轮制作中最容易混淆：

- 哪份剧本被确认；
- 哪张图是正式资产；
- 哪次提示词生成了哪个视频；
- 哪个结果已经采用；
- 下一段依赖哪个真实结束状态。

建议在项目内创建：

```text
productionState.md
```

多集项目可每集一个子目录或状态文件。

### 17.2 最小状态模板

```markdown
# 制作状态

本次目标与范围：
当前画布：
源剧本及固定版本：
当前阶段：
已授权范围：
待处理事项：

## 成果
| 标识 | 用途/场次 | 版本 | 画布/节点 | 正文或媒体路径 | 固定版本 | 输入依赖 | 状态与确认依据 |
|---|---|---|---|---|---|---|---|

## 生成尝试
| 尝试标识 | 资产/片段 | 提示词快照 | 模型与参数 | 参考与顺序 | 调用前输出 | 授权次数 | 返回与实际文件 |
|---|---|---|---|---|---|---|---|

## 片段采用
| 片段 | 剧情范围 | 采用文件 | 拟用区间 | 实际结束状态 | 核验者 | 后续依赖 |
|---|---|---|---|---|---|---|

## 交付
实际交付文件及顺序：
已生成范围：
已采用范围：
已合成范围：
尚缺内容：
```

### 17.3 状态词统一

建议只使用：

```text
待设计 → 待生成 → 生成中 → 待验收 → 已采用
                                  ↘ 作废
```

“提示词已写完”不等于“已生成”；“生成成功”不等于“已采用”；“所有片段已采用”不等于“已合成成片”。

### 17.4 不覆盖历史

- 确认文本前保存快照；
- 生成前保存提示词和参数快照；
- 修订使用新候选节点；
- 已采用媒体保留原件；
- 只有受影响的下游需要更新；
- 不根据文件名中的“最终版”或修改时间猜测采用状态。

## 18. 完成交付

### 18.1 Toonflow 内可交付的内容

- 已确认剧本和制作简报；
- 角色、场景、道具资产；
- 分段视频提示词；
- 已生成并采用的视频片段；
- 音频和旁白文件；
- 3D 预演或关键帧；
- 片段顺序与拟用区间；
- 制作状态和缺项说明。

### 18.2 交付清单模板

```text
项目：雨夜来客 第01集
剧本：episode01ScriptV3.md，用户于 <时间> 确认
画幅：9:16
目标时长：60 秒

已采用资产：
- C01 女捕快基础态：assets/characters/c01.png
- C02 掌柜基础态：assets/characters/c02.png
- S01 雨夜客栈：assets/scenes/s01.png

已采用视频：
1. V01 进店亮令牌：assets/generated/video....mp4，拟用 00:00–00:10
2. V02 掌柜抽刀：assets/generated/video....mp4，拟用 00:10–00:18

核验：
- 图片：Agent 与用户共同核验
- 视频：用户完整预览采用；Agent 未完整审听音轨

仍需后期：
- 精确裁切
- 字幕
- 配乐与混音
- 片头片尾
- 最终 1080×1920 H.264 导出
```

### 18.3 外部后期建议

将已采用片段导入剪辑软件，按状态表顺序完成：

1. 裁掉模型常见的开头/结尾无效帧；
2. 校准片段连接和节奏；
3. 添加对白字幕、标题和实体文字修复；
4. 添加或替换配音、环境音、音效和音乐；
5. 统一响度；
6. 必要时做色彩匹配和画面修复；
7. 输出目标平台规格；
8. 回写最终成片路径和版本到状态文件。

## 19. 一套可直接照做的完整示例

以下示例是一部 45–60 秒竖屏古风漫剧。

### 第一步：创建项目

工作目录：

```text
D:\ToonflowProjects\雨夜来客01
```

首页输入：

```text
制作一部 45–60 秒、9:16、国风厚涂的悬疑漫剧。女捕快雨夜进入客栈，发现掌柜与一封血书有关。先只完成剧本和资产方案，不生成媒体。请使用 workflow 技能，重要改编先让我确认。
```

### 第二步：确认范围

确定：

- 单集完整故事；
- 两名出镜角色；
- 一个主场景；
- 一个关键道具；
- 中文对白；
- 字幕后期添加；
- 本轮先定稿剧本和资产清单。

### 第三步：定稿剧本

Agent 把完整剧本写入“第01集剧本”文本节点，用户在文档面板修改并确认。保存快照：

```text
history/episode01ScriptV1.md
```

### 第四步：资产清单

```text
C01 女捕快基础态
C02 客栈掌柜基础态
S01 雨夜客栈大堂
P01 血书基础态
```

确认角色外观、客栈空间和道具结构。

### 第五步：生成资产

建立四个图片生成候选节点，逐一展示模型、提示词、规格和参考。用户授权后生成。

验收后用独立图片节点固定：

```text
C01 女捕快 已采用
C02 掌柜 已采用
S01 客栈 已采用
P01 血书 已采用
```

### 第六步：规划视频

用户选择 Seedance 2.5。Agent按定稿剧本规划：

```text
V01 进店与亮令牌，10 秒
V02 掌柜试探与血书出现，12 秒
V03 短暂冲突与身份揭示，12 秒
V04 收束与悬念结尾，12 秒
```

每段形成正式提示词并确认。

### 第七步：搭建生成节点

建立四个视频生成节点。V01 连接 C01、C02、S01；V02 根据剧情再加入 P01。检查引用顺序和 9:16、时长、分辨率、音频设置。

### 第八步：分批生成

先只生成 V01。用户完整预览并报告结束时：

```text
女捕快站在柜台外偏左，面向右前方；右手压住令牌。
掌柜在柜台内偏右，身体稍后仰，右手刚移到柜台下。
血书尚未出现。
```

将它写入 V02 初始状态，再生成 V02。依次完成后续片段。

### 第九步：采用与交付

用户从每段候选中选择正式版本，状态文件登记真实路径、顺序和核验情况。最后把四段导入外部剪辑软件，完成字幕、声音和最终输出。

## 20. 给 AI Agent 的完整操作协议

这一节可以直接提供给 DeepSeek Harness、Toonflow Agent 或其他接管 Agent。

### 20.1 总原则

1. 先读取 `workflow` Skill 正文，不凭简介执行。
2. 以用户明确输入、已确认版本和真实文件为事实源。
3. 区分事实、提案、未知项、生成中、已生成、已采用和已合成。
4. 默认在当前项目和当前画布工作，不猜路径、节点、端口、模型或函数。
5. 不直接编辑画布 JSON；使用画布工具和节点函数。
6. 只创建当前阶段需要的节点，不提前铺满整个流程。
7. 内容确认、生成授权和结果采用分别取得。
8. 生成媒体前展示对象、数量、模型、规格、完整提示词、真实参考、次数和算力消耗。
9. 工具失败后先读最新状态，不盲目重试。
10. 没有真实查看能力时，明确请用户验收，不假称已审片。
11. 只更新受变更影响的资产和片段，保留已采用历史。
12. 当前没有成片工具时，交付片段索引和后期缺项，不声称已合成。

### 20.2 AI 标准阶段循环

每个阶段按以下循环执行：

```text
读取当前真实状态
  → 判断本轮唯一目标
  → 只问关键缺项
  → 形成可审阅成果
  → 保存具体版本
  → 请求内容确认
  → 若涉及生成，另给生成方案并请求授权
  → 执行真实工具
  → 回读真实结果
  → 请求或完成质量核验
  → 记录采用与下一阶段依赖
```

### 20.3 AI 首次接手已有项目

```text
请接管当前 Toonflow 项目，但先不要修改和生成。
1. 使用 workflow 技能；
2. 读取当前工作区、活动画布、剧本文档、productionState.md、已采用资产和视频节点；
3. 区分已确认、候选、生成中、已采用和未知；
4. 给出当前阶段、真实成果、缺项、风险和唯一推荐下一步；
5. 不根据节点名称或文件时间猜版本。
```

### 20.4 AI 从创意开始

```text
请使用 workflow 技能，把下面的创意发展成可制作的短剧/漫剧。
先完成本次范围、故事因果和完整可审阅剧本；必要问题合并询问。未经我确认不要制作正式资产，不要生成图片或视频。

创意：<内容>
目标时长：<时长>
画幅：<比例>
类型与风格：<短剧/漫剧及风格>
```

### 20.5 AI 从小说改编

```text
请使用 workflow 技能读取我指定的小说范围，记录实际覆盖章节和未读部分。先提取事件、人物关系、关键对白、地点、道具状态和悬念，再把心理活动转为可见行动或声音。新增、删并和改视角必须标为改编提案；未经确认不要改原著关键事实，也不要生成媒体。
```

### 20.6 AI 从定稿剧本进入制作

```text
这是定稿剧本。请固定此版本，不重新编剧。使用 workflow 技能提取本集角色、场景、道具、声音和持续状态，给出完整资产清单和缺失资产设计方案。先不要消耗算力。
```

若随后开始制作视频且未指定 Seedance 版本，AI 应先问：

```text
本次视频提示词按 Seedance 2.0 还是 2.5 制作？
```

### 20.7 AI 只搭画布不生成

```text
请使用 canvas 工具在当前画布落实已经确认的剧本和资产清单。只创建当前阶段需要的文本节点、图片素材节点和候选生成节点，按从左到右排列。回读并核对保存结果；不要启动任何媒体生成。
```

### 20.8 AI 准备生成方案

```text
请只为 <资产或片段标识> 准备一次生成方案。读取节点实时能力和真实参考顺序，给出对象、数量、providerId/modelId、规格、完整提示词、参考文件与用途、次数和算力消耗。不要在我明确授权前调用生成。
```

### 20.9 AI 处理生成完成

```text
<节点/片段> 已显示生成完成。请回读节点输出和真实文件，核对它是否为本次尝试。按实际能力检查；如果不能完整查看视频或音轨，请明确列出需要我预览确认的问题，不要直接登记采用。
```

### 20.10 AI 做局部修订

```text
只修订 <标识> 的 <具体问题>。先追踪它实际影响的资产、片段和交界状态，保留未受影响的确认和旧采用版本。新建候选，不覆盖当前正式结果；若需要额外生成，先给出变更后的方案和授权范围。
```

## 21. 常见问题与恢复

### 21.1 首页无法选择工作目录

- 桌面端：确认原生目录窗口未被其他窗口遮挡；
- Server 版：只能选择服务器 `data/workspaces` 内目录；
- 检查目录是否存在、是否有权限；
- 新项目目录必须为空；
- 不要把文件路径当目录路径。

### 21.2 打开工作区后没有项目

可能是直接访问了 `#/workspace`，但没有从首页选择项目。返回首页重新打开或导入项目。

### 21.3 看不到节点

- 打开“设置 → 插件市场”；
- 检查节点是否已安装和启用；
- 源码开发首次运行先执行 `bun run dev:plugins`；
- 刷新页面后重新打开项目；
- 不直接编辑 `data/nodes` 产物。

### 21.4 模型列表为空

- 检查“设置 → 文本模型/媒体模型”；
- 检查 API Key、API URL 和协议；
- 检查模型类型是否为当前节点需要的 image/video/audio；
- 尝试重新读取模型列表；
- 查看供应商调试信息，但不要公开密钥。

### 21.5 图片/视频不能生成

检查：

- 提示词是否为空；
- 是否已选择模型；
- 模型是否支持当前参考数量和类型；
- 时长、分辨率、比例和 mode 是否兼容；
- 参考文件是否仍存在；
- API Key 和余额是否正常；
- 页面是否切换或关闭；
- 是否需要 FFmpeg。

### 21.6 节点一直显示生成中

- 不要立即重试；
- 查看节点是否出现新输出；
- 查看错误提示；
- 确认请求是否因页面切换中止；
- 必要时停止后检查供应商任务；
- 重新生成前确认是否会再次消耗算力。

### 21.7 保存失败

- 保持页面打开；
- 点击重试；
- 检查工作区磁盘、权限和文件占用；
- 确认没有另一个 Toonflow 实例编辑同一项目；
- 不要在保存中移动或删除项目目录；
- 强制退出前先复制尚未保存的文本。

### 21.8 画布很乱或找不到节点

- 使用“适应视图”；
- 打开小地图；
- 使用节点搜索；
- 只在确定要整理整张画布时点击“整理画布”；
- 局部内容用框选后的水平、垂直或宫格排列；
- 整理不满意时及时撤销。

### 21.9 参考顺序错误

- 打开生成节点参考列表；
- 检查每条实际连线；
- 重新排序参考；
- 同步修改 `{{ref N}}`；
- 首尾帧模式重新确认首帧、尾帧；
- 不要在空引用存在时继续生成。

### 21.10 Agent 做错或做多了

立即停止生成，然后说明：

```text
停止扩展范围。只保留 <已确认内容>，撤销/删除本轮误创建且未被采用的 <节点或内容>。先读取最新画布和文件，列出将保留、将删除和不会触碰的项目，等我确认后再执行。
```

注意删除可能影响真实文件和下游连接，必须先核对。

### 21.11 视频结果不连贯

- 先判断两段是否真的需要连续；
- 读取前段真实结束状态，而不是计划状态；
- 检查人物位置、朝向、姿势、持物和场景；
- 必要时用真实接戏帧作为下一段参考；
- 当前段有穿帮先修当前段，不让后段继承错误。

### 21.12 最后没有一个“成片文件”

这是当前产品边界。确认已采用片段、顺序和音频后：

- 若已有可用合成工具，明确授权并实际执行；
- 否则导出到外部剪辑软件；
- 不把多个片段文件称为已经合成的成片。

## 23. 最终原则

1. 先把故事做对，再做漂亮的资产。
2. 先确认资产，再让它进入视频。
3. 先写完片段提示词，再连接真实参考和设置模型。
4. 先明确授权，再消耗算力。
5. 生成完成后先验收，不能自动采用。
6. 连续性以真实生成结果为准，不以计划为准。
7. 修订只影响真实依赖，不重做整个项目。
8. 所有确认都绑定具体版本。
9. 所有交付都使用真实文件路径。
10. Toonflow 做到哪里就如实交付到哪里；没有完成剪辑，就不要把片段集合称为成片。
